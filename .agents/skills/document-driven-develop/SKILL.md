# Document-Driven Develop（文档驱动开发）

## 1. 核心原则

本仓库遵循文档驱动开发：文档是唯一真实来源，代码必须对齐文档。

**硬性门禁：改代码前先改相关文档。** 任何代码修改（新增、行为变更、修 bug 导致的行为变化）都必须先定位受影响的文档章节，完成对应修改并自检，然后才允许动代码。文档未同步的代码变更一律视为违规，不得提交。

```text
Doc → Check → Code → Sync
```

- **Doc**：先写/先改文档，明确对外承诺什么行为。
- **Check**：把文档里的每个示例和行为点转成验收标准。
- **Code**：只实现文档写过的行为，让代码对齐文档。
- **Sync**：实现中发现偏差，先改文档，再改代码。

禁止先写实现后补文档。没有对应文档的行为，视为未定义行为，不应出现。

## 2. 与其它流程的关系

| 流程 | 决定什么 |
| --- | --- |
| `intent-spec-impl` | 做什么（内部规格，落地到 `docs/specs/`） |
| **本流程** | 对外承诺什么（文档即契约） |
| `tdd` | 怎么实现（测试先行） |

三者可叠加，推荐顺序：Intent → Doc → Test → Code。

## 3. 工作流程

### 步骤 0：定范围

- 明确目标读者：使用者、集成方、维护者。
- 列出本次变更涉及的对外面：命令、API、配置项、环境变量、文件格式、错误码。
- 写出 non-goals，防止文档承诺范围蔓延。

### 步骤 0.5：Find — 定位受影响文档

- 用 `grep` / `rg` 搜索本次要改的接口名、命令名、配置键、错误信息、环境变量，找出所有引用它的文档。
- 列出待改文档清单：文件路径 + 章节 + 需要改成什么。
- 找不到对应文档时，先在文档中补齐现状（当前真实行为），再开始改代码。
- 清单为空但变更确有对外影响 → 说明文档缺失，先补文档，不允许"先改代码回头补"。

### 步骤 1：Doc — 先写文档

落到项目已有的文档位置（README、`docs/`、`docs/api/` 等）；仓库无约定时新建 `docs/<feature>.md`，slug 用英文短横线。正文中文，代码示例英文。

每份文档必须覆盖：

1. **用途**：一句话说明解决什么问题。
2. **用法示例**：可直接复制的输入与输出。
3. **参数 / 返回值 / 配置项**：名称、类型、默认值、是否必填。
4. **错误与边界**：失败场景、错误信息、退出码。
5. **兼容性与迁移**：破坏性变更、旧写法如何改。

### 步骤 2：Check — 文档即验收标准

- 每个示例标注 `<!-- runnable -->` 或 `<!-- manual -->`。
- `runnable` 的示例挂到 doctest / `docs/examples/*.sh` / 测试用例，先运行一次，确认它当前失败（说明行为还没实现或尚未对齐）。
- `manual` 的示例列出人工校验点。
- 每个可观察行为对应一条验收标准；无法验证的描述直接删掉。

### 步骤 3：Code — 实现到对齐

- 动代码前，确认步骤 0.5 清单中的文档已全部改完；文档 diff 必须早于代码 diff。
- 只实现文档写过的行为，不夹带未文档化功能（YAGNI）。
- 代码 diff 与文档 diff 一一对应：每个行为改动都能对上一条文档改动，反之亦然。
- 实现中发现文档不可行：先改文档并说明原因，再改代码。不允许"代码是对的，文档回头再补"。
- 错误信息、默认值、退出码必须与文档逐字一致。

### 步骤 4：Sync — 校验与回写

- 逐条对照文档，跑通所有 `runnable` 示例。
- 检查是否存在未文档化的实际行为，补齐文档或删除代码。
- 更新 CHANGELOG 或版本说明（若项目有）。

### 步骤 5：提交

- `docs:` 提交先于 `feat:` / `fix:` 提交；同一变更内文档与代码成对出现，不拆开合入。
- 提交信息遵循 Conventional Commits。
- 用 `git log --oneline` 自检：`docs:` 提交必须排在对应 `feat:` / `fix:` 提交之前，不允许合并成一条含糊的 `chore:`。

## 4. 豁免

- 仅文档修订，不改代码。
- 注释、格式化、拼写修正等无行为变化的改动。
- 一次性实验代码（不得合入主干）。

## 5. 自查清单

- [ ] 代码变更前，文档已存在并描述了该行为
- [ ] 改代码前已完成受影响文档的修改，文档 diff 先于代码 diff
- [ ] 每个代码改动点都能对上一条文档改动
- [ ] 文档覆盖用法示例、参数、错误、兼容性
- [ ] `runnable` 示例全部真实跑通
- [ ] 错误信息、默认值与文档逐字一致
- [ ] 没有未文档化的新行为
- [ ] `docs:` 提交在 `feat:` / `fix:` 之前
