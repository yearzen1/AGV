# 答辩演示脚本

> 目标时长 8–10 分钟。全程使用固定随机种子，保证现场可复现。

## 零、演示前检查（提前 10 分钟）

```powershell
# 1. 后端
cd agv-backend
mvn spring-boot:run

# 2. 前端（另开一个终端）
cd agv-frontend
npm run dev
```

- 打开 <http://localhost:5173>，确认能登录。
- 确认 `agv-backend/data/agvdb.mv.db` 已存在（演示数据已初始化）。
- 关闭无关窗口，浏览器缩放 100%。
- 备用方案：若现场网络或依赖异常，直接使用已构建的 `agv-frontend/dist` 与本机后端。

## 一、管理员视角（约 1.5 分钟）

1. 以 `admin / admin123` 登录。
2. 进入「用户管理」，说明两类角色与启停控制，展示调度人员账号。
3. 进入「数字字典」，选择「调度算法」，把「贪心 ETA」的显示名改一下再改回，说明下拉框由此统一取值。

**讲述要点**：管理员比调度人员多两个菜单；权限在后端 `@PreAuthorize` 上也有校验，不只是前端隐藏。

## 二、车间地图（约 2 分钟）

1. 切换到 `dispatcher / dispatcher123` 登录。
2. 进入「车间地图」，选择「标准车间（双充电位）」，说明 10 节点 / 11 路段。
3. 点击「另存为」，命名为「答辩演示路网」。
4. 在画布上：
   - 用「工位」工具在空白处点击，新增一个节点；
   - 切到「连路段」，先点新节点再点 W1，生成一条双向路段；
   - 切到「选择/拖动」，拖动新节点，观察关联路段长度自动变化；
   - 点「校验」，展示通过或定位错误；
   - 点「保存」。
5. 点「导出 JSON」，说明可批量迁移。

**讲述要点**：画布底纹只是对齐网格，存储的仍是节点与路段，不是栅格地图。保存前后端各校验一次。

**兜底**：若现场拖拽不顺，直接演示「套用模板 → 另存为 → 保存」，并说明画布建图在第 3 周即通过验收。

## 三、仿真运行（约 3 分钟）

1. 进入「任务集」，展示「演示任务集（20 单）」，说明起终点在三个工位之间循环。
2. 进入「仿真运行」：
   - 选择标准车间、演示任务集；
   - 算法选「就近分配」，AGV 数量 5，种子 20261107；
   - 点「开始」。
3. 观察三维场景：车辆沿路段平滑移动，等待时变红，装卸时变橙。
4. 讲解右侧指标：tick、完成数、完成时间、冲突次数、总里程、总等待。
5. 等待出现 1–2 条「冲突等待」日志，暂停仿真，放大日志面板讲解。
6. 调速到 4x，继续运行至结束。

**讲述要点**：后端每 100 ms 推一帧，前端插值渲染；等待发生在节点上，不会停在路段中间。

**兜底**：若 WebSocket 异常，刷新页面重连；仍不行则切到「对比实验」用离线结果讲解。

## 四、算法对比（约 2.5 分钟）

1. 进入「对比实验」，选择同一路网与任务集，AGV 数量 8，种子 20261107。
2. 点「运行对比（两种算法）」。
3. 展示柱状图与表格，读出两组数据：
   - 就近分配：完成时间约 3695 tick，冲突 133 次；
   - 贪心 ETA：完成时间约 3653 tick，冲突 132 次。
4. 切换 AGV 数量为 2 再跑一次，说明低负载下贪心 ETA 更快（3338 对 3948）。
5. 下拉到「我的历史实验」，说明按创建人隔离、可回看。

**讲述要点**：同一路网、同一任务集、同一随机种子，两个算法共用同一套避障逻辑，因此差异只来自任务分配。低负载时贪心 ETA 的总路径更短；高负载时路口容量为 1，两者完成时间接近，贪心 ETA 的等待略低。

## 五、难点讲解（约 1 分钟，老师常问）

**问题**：双向车道下多车互相等待会死锁。

**回答要点**：

1. 路口被建模为容量 1 的临界区，同一时刻只允许一辆车通过，等待车辆保持路口占用；
2. 车辆只预约下一段弧与目标节点，节点预约从实际到达 tick 开始；
3. 每 10 tick 检测等待环，先尝试倒车让行；倒车不可行时由最低优先级车辆让出路口并带禁行重规划；等待 30 tick 也会触发绕行；
4. 单车道双向串行，双车道双向可对向同时通行；
5. 改进后 2/3/5/8 台车的 8 组配置全部完成 20 单，数据见论文表 6-2。

## 六、可能的追问

| 问题 | 回答要点 |
|---|---|
| 为什么用拓扑路网不用栅格？ | 车道有方向、限速、容量，栅格表达不了；路口需要显式节点才能做节点级冲突判定 |
| A\* 为什么状态要带入边？ | 代价含转弯惩罚，同一节点从不同来向到达的后续代价不同，只按节点关闭会次优 |
| 时间窗是怎么做的？ | 逐段滚动预约，只占下一段弧与目标节点，等待超时再带禁行重规划 |
| 你的创新点是什么？ | 可自由建图的环境 + 可复现的冲突消解 + 统一口径的算法对比报表 |
| 仿真和真实系统的关系？ | 仿真的是环境，调度算法是真实代码；对应现实中的 Fleet Manager 层 |
| 为什么不做车端避障？ | 那是设备固件与安全认证范畴（ISO 3691-4），不属于调度层 |
