# 摘要

## 中文摘要

随着智能制造与仓储物流自动化的发展，AGV 集群已成为车间物料搬运的核心装备。多台 AGV 的调度涉及任务分配、路径规划与冲突消解三个相互耦合的问题，其效果高度依赖路网结构与调度策略。真实环境下的对比实验需要高昂的设备投入，且路径冲突与死锁在真车上表现为碰撞，试错成本不可接受。为此，本文设计并实现了一套面向车间的多 AGV 路径规划仿真与调度可视化系统。

系统仿真的是调度算法的运行环境，调度算法本身是真实运行的代码。系统以拓扑路网描述车间，节点区分拣货位、上货位、存储位、充电位、停放位、缓存位与路口；充电区、停放区、存储区、拣货区和上货区用只做布局标注的区域表达。路段携带长度、单双向、速度与容量；加载时把双向路段拆分为正反两条有向弧。任务用装货/卸货标注约束端点方向，装货与卸货可以配置不同的服务时间。路径规划采用图上 A\*，把搜索状态扩展为"节点 + 入边"二元组以正确处理转弯惩罚，并以状态空间 Bellman-Ford 作为参考解在随机路网上完成对拍验证。

冲突消解采用逐段滚动预约：车辆只预约下一段弧与目标节点，等待期间释放节点占用。该设计使资源持有者必为行驶中的车辆，从结构上排除了资源等待环；辅以等待超时重规划与等待环检测作为兜底。任务分配实现就近分配与贪心 ETA 两种策略，二者在同一路网、任务集与随机种子下对比。

系统采用 Spring Boot + Vue 3 + Three.js + WebSocket 实现，后端以 100 ms 为周期推送车辆位置与事件，前端插值渲染三维场景，支持暂停、调速与重置。在包含 26 个节点、31 条路段和 5 个区域的仓储车间与 20 个任务的演示任务集上，完成了 2、3、5、8 台车与两种算法的 8 组对比实验。结果表明：固定种子下指标完全可复现；就近分配在 2–8 台范围内持续降低完成时间，贪心 ETA 在 8 台时因上货位与存储支路排队而反弹；两种策略各有适用区间；等待时间比冲突次数更能反映路网饱和度。

**关键词**：AGV；路径规划；A\* 算法；时间窗；冲突消解；仿真可视化

## Abstract

With the development of intelligent manufacturing and warehouse logistics, AGV fleets have become core equipment for material handling in workshops. Multi-AGV scheduling involves task assignment, path planning and conflict resolution, and its performance depends heavily on the road network and dispatching strategy. Experiments in real environments require expensive hardware, and path conflicts or deadlocks appear as collisions on real vehicles, making trial and error unacceptable. This thesis designs and implements a workshop-oriented multi-AGV path planning simulation and scheduling visualization system.

What the system simulates is the operating environment of scheduling algorithms, while the algorithms themselves are real, running code. The workshop is modeled as a topological network, where nodes are classified into picking, loading, storage, charger, parking, buffer and junction nodes, while charging, parking, storage, picking and loading areas are layout annotations only. Edges carry length, direction, speed and capacity. Bidirectional edges are split into two directed arcs at load time. Path planning adopts graph A\* with the search state extended to a (node, incoming arc) pair so that turn penalties are handled correctly; a state-space Bellman-Ford reference implementation is used for cross-validation on random graphs.

Conflict resolution adopts segment-by-segment rolling reservation: a vehicle reserves only the next arc and the target node, and releases its node occupancy while waiting. Consequently, resource holders are always moving vehicles, which structurally eliminates resource wait cycles. Timeout-based replanning and wait-cycle detection serve as fallbacks. Two dispatching strategies, nearest assignment and greedy ETA, are compared under the same network, task set and random seed.

The system is implemented with Spring Boot, Vue 3, Three.js and WebSocket. The backend pushes vehicle positions and events every 100 ms, and the frontend interpolates them in a 3D scene with pause, speed control and reset. Experiments on a warehouse network with 26 nodes, 31 edges and five layout areas, using a 20-task set and fleet sizes of 2, 3, 5 and 8, show that: results are fully reproducible under a fixed seed; nearest assignment keeps reducing makespan from 2 to 8 vehicles, while greedy ETA rebounds at 8 vehicles due to queues at loading stations and storage spurs; each strategy has its own applicable range; and waiting time is a more sensitive indicator of network saturation than conflict count.

**Keywords**: AGV; path planning; A\* algorithm; time window; conflict resolution; simulation visualization
