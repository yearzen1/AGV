# 摘要

## 中文摘要

随着智能制造与仓储物流自动化的发展，AGV 集群已成为车间物料搬运的核心装备。多台 AGV 的调度涉及任务分配、路径规划与冲突消解三个相互耦合的问题，其效果高度依赖路网结构与调度策略。真实环境下的对比实验需要高昂的设备投入，且路径冲突与死锁在真车上表现为碰撞，试错成本不可接受。为此，本文设计并实现了一套面向车间的多 AGV 路径规划仿真与调度可视化系统。

系统仿真的是调度算法的运行环境，调度算法本身是真实运行的代码。系统以拓扑路网描述车间，节点区分工位、充电位、缓存位与路口，路段携带长度、单双向、速度与容量；加载时把双向路段拆分为正反两条有向弧。路径规划采用图上 A\*，把搜索状态扩展为"节点 + 入边"二元组以正确处理转弯惩罚，并以状态空间 Bellman-Ford 作为参考解在随机路网上完成对拍验证。

冲突消解采用逐段滚动预约：车辆只预约下一段弧与目标节点，节点容量严格约束物理停靠。为从根源上消除死锁，本文把约束前移到拓扑：路网必须全部单向、没有叶子节点、有向图强连通，并据此证明只要车队数小于加权环容量，等待图就不可能成环。车队上限同时受充电位过道位数量约束，超编在启动阶段即被拒绝。任务分配实现就近分配与贪心 ETA 两种策略，二者在同一路网、任务集与参数下对比。

系统采用 Spring Boot + Vue 3 + Three.js + WebSocket 实现，后端以 100 ms 为周期推送车辆位置与事件，前端插值渲染三维场景，支持暂停、调速与重置。在包含 8 个节点、8 条单向路段的标准车间与 20 个任务的演示任务集上，完成了 1 至 6 台车与两种算法的 12 组对比实验。结果表明：引擎不含随机源，20 个种子下结果完全一致；全部 12 组配置都完成 20 单，结构约束使死锁不可表达；规模收益在第 5 台后基本饱和，就近分配 5 台到 6 台只缩短 1 tick 却多跑 192 米；贪心 ETA 在 2 至 6 台上全面优于就近分配，差距 3.3% 至 20.0%，原因是单向环放大了欧氏距离与实际路径的偏差；12 组配置的物理超容均为 0。

**关键词**：AGV；路径规划；A\* 算法；时间窗；冲突消解；结构无死锁；仿真可视化

## Abstract

With the development of intelligent manufacturing and warehouse logistics, AGV fleets have become core equipment for material handling in workshops. Multi-AGV scheduling involves task assignment, path planning and conflict resolution, and its performance depends heavily on the road network and dispatching strategy. Experiments in real environments require expensive hardware, and path conflicts or deadlocks appear as collisions on real vehicles, making trial and error unacceptable. This thesis designs and implements a workshop-oriented multi-AGV path planning simulation and scheduling visualization system.

What the system simulates is the operating environment of scheduling algorithms, while the algorithms themselves are real, running code. The workshop is modeled as a topological network, where nodes are classified into workstations, chargers, buffers and junctions, and edges carry length, direction, speed and capacity. Every edge is one-way and is mapped to a single directed arc. Path planning adopts graph A\* with the search state extended to a (node, incoming arc) pair so that turn penalties are handled correctly; a state-space Bellman-Ford reference implementation is used for cross-validation on random graphs.

Conflict resolution adopts segment-by-segment rolling reservation: a vehicle reserves only the next arc and the target node, while node capacity strictly limits physical occupancy. To eliminate deadlock at its root, the constraint is moved into the topology: every edge must be one-way, no node may have degree one, and the directed graph must be strongly connected. Under these invariants we prove that no wait-for cycle can form as long as the fleet size stays below the weighted cycle capacity. The fleet cap is further bounded by the number of parking slots, since a fully occupied charger would cut the single loop; requests above the cap are rejected at startup. Two dispatching strategies, nearest assignment and greedy ETA, are compared under the same network, task set and parameters.

The system is implemented with Spring Boot, Vue 3, Three.js and WebSocket. The backend pushes vehicle positions and events every 100 ms, and the frontend interpolates them in a 3D scene with pause, speed control and reset. Experiments on a standard one-way ring with 8 nodes and 8 edges, using a 20-task set and fleet sizes from 1 to 6, show that: the engine contains no random source, so all 20 tested seeds give identical results; all 12 configurations complete the 20 tasks, because deadlock is structurally inexpressible; the marginal gain vanishes after five vehicles, where nearest assignment saves one tick while driving 192 extra meters; and greedy ETA outperforms nearest assignment at every fleet size from 2 to 6 by 3.3% to 20.0%, because a one-way ring amplifies the gap between Euclidean distance and the real route.

**Keywords**: AGV; path planning; A\* algorithm; time window; conflict resolution; structural deadlock avoidance; simulation visualization
