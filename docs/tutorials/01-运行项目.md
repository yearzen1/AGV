# 教程：从零运行「排策智演」

> **读者**：会 Java、会 Node.js，但没写过 Spring Boot，也没写过 Vue。
> **目标**：不读源码，按步骤把项目跑起来，并完整走一遍演示流程。
> **用时**：首次约 30～40 分钟，大部分时间在下载依赖。

跟着做完，你会看到：后端在 `8080` 提供接口，前端在 `5173` 打开登录页，3D 场景里 3 台 AGV 跑完 20 个任务，对比实验画出两张算法的指标图。

---

## 0. 路线图

```
装环境 → 认识目录 → 根目录 install → 起后端(8080) → 起前端(5173) → 登录冒烟 → 业务演示 → 停止
```

每一步都有「命令」和「你应该看到什么」。看到的东西对不上，直接跳到第 10 节排错。

---

## 1. 三个新东西，先有个抓手（3 分钟）

你不需要先学会它们，只要知道谁先启动、谁依赖谁。用你已经会的东西对照：

| 你已经会的 | 这个项目里的 | 一句话关系 |
|---|---|---|
| Express + `node server.js` | Spring Boot + `mvn spring-boot:run` | 都是「起一个 HTTP 服务」。`@GetMapping` 就是 `app.get`，`application-dev.yml` 就是 `.env` + 配置 |
| `npm install` / `package.json` | `mvn install` / `pom.xml` | 都是装依赖。区别是 Maven 把包装进本地仓库（默认 `~/.m2`），不是 `node_modules` |
| Vite / Webpack dev server | Vite（同款） | `npm run dev` 起 5173，`vite.config.ts` 把 `/api`、`/ws` 代理到 8080 |
| 前端框架 | Vue 3 | 一个 `.vue` 文件 = 模板 + `<script setup>` + `<style>`，不用先学也能跑 |

数据的流向只有一条：

```
浏览器 → 5173(Vite 开发服务器) --/api、/ws--> 8080(Spring Boot) --> H2 数据库文件
```

另外要记住一点：后端依赖一个纯 Java 算法包 `agv-algorithm`，而仓库里**没有编译好的 jar**，所以第 3 步不能跳。

---

## 2. 装好三样东西

| 组件 | 版本 | 验证命令 | 应该看到 |
|---|---|---|---|
| JDK | 17 | `java -version` | `openjdk version "17.x"` |
| Maven | 3.6+ | `mvn -v` | `Apache Maven 3.x`，且 `Java version: 17` |
| Node.js | 18+ | `node -v` / `npm -v` | `v18.x` 或更高 / `npm 9.x+` |
| MySQL | 不需要 | — | 默认用 H2 文件库，零安装 |

Windows 安装（PowerShell，装完**重开终端**）：

```powershell
winget install EclipseAdoptium.Temurin.17.JDK
winget install Apache.Maven
winget install OpenJS.NodeJS.LTS
```

macOS / Linux 参考：

```bash
brew install openjdk@17 maven node
```

**关键检查**：`mvn -v` 输出里的 `Java version` 必须是 17。如果显示 1.8 或 11，说明 Maven 用错了 JDK，先设置 `JAVA_HOME` 指向 JDK 17 再继续。

## 3. 拿到代码，认识目录

```powershell
cd <项目根目录>
# 例如本机：cd C:\Users\jiahui\Desktop\project\AGV
```

（如果是新机器，先 `git clone` 再进入目录。）

| 目录 | 是什么 | 这次要不要动 |
|---|---|---|
| `agv-algorithm/` | 纯 Java 算法包：路网、A\*、时间窗、仿真引擎，零 Spring 依赖 | 不动 |
| `agv-backend/` | Spring Boot 后端：登录鉴权、CRUD、仿真编排、WebSocket | 不动 |
| `agv-frontend/` | Vue 3 + Element Plus + Three.js 前端 | 不动 |
| `scripts/` | 启动 / 停止 / 生成论文的脚本 | 用 `dev.ps1`、`stop-dev.ps1` |
| `docs/` | 文档，本教程在这里 | 读 |
| `paper/` | 论文、答辩 PPT、演示脚本 | 读 |
| `specs/` | 实施计划、时间安排 | 读 |

依赖关系：

```
agv-backend  ──依赖──>  agv-algorithm
agv-frontend ──HTTP/WS──>  agv-backend ──> H2(或 MySQL)
```

## 4. 第一条关键命令：把算法包装进本地仓库

在**仓库根目录**执行：

```powershell
mvn -DskipTests install
```

首次会下载一堆依赖，几分钟正常。成功的标志：

```
[INFO] agv-algorithm ...................................... SUCCESS
[INFO] agv-backend ........................................ SUCCESS
[INFO] BUILD SUCCESS
```

同时本地仓库会出现 `com/agv/agv-algorithm/1.0.0/`。本地仓库默认在 `~/.m2/repository`（Windows 是 `C:\Users\<你>\.m2\repository`）；如果你改过 Maven 的 `settings.xml`，以实际配置的 `localRepository` 为准，可以用 `mvn help:evaluate -Dexpression=settings.localRepository -q -DforceStdout` 查看。

**为什么不能跳过**

`agv-backend/pom.xml` 里写着依赖 `com.agv:agv-algorithm:1.0.0`，但仓库里只有源码，没有这个 jar。如果直接 `cd agv-backend` 再 `mvn spring-boot:run`，会报：

```
Could not resolve dependencies ... com.agv:agv-algorithm:jar:1.0.0
```

根目录的 `install` 会先编译算法包并装进本地仓库，后端才找得到。

（可选）想顺带跑一遍单元测试，把 `-DskipTests` 去掉即可：`mvn test`。会多花几分钟，不是跑起来的必要条件。

## 5. 启动后端（终端 A）

**新开一个终端**，留在后端目录：

```powershell
cd agv-backend
mvn spring-boot:run
```

首次启动会继续下载 Spring 相关依赖。看到下面几行就算起来了：

```
Tomcat started on port 8080 (http) with context path ''
Started AgvBackendApplication in 5.123 seconds
```

**第一次**启动还会看到初始化日志（第二次起不会重复打印，正常）：

```
初始化账号 admin / admin123（角色 admin），首次登录后请修改密码
初始化账号 dispatcher / dispatcher123（角色 dispatcher），首次登录后请修改密码
H2 console available at '/h2-console'
```

验证后端（浏览器直接打开，或另开终端）：

```powershell
curl http://localhost:8080/api/health
```

预期：

```json
{"code":0,"message":"ok","data":{"service":"agv-backend","status":"UP","time":"2026-11-08T10:00:00"}}
```

只要 `status` 是 `UP`，说明 Web 服务、数据库、初始化都正常。

补充说明：

- 默认配置是 `dev`（`application.yml` 里 `profiles.active: dev`），数据库是 H2 文件库：`agv-backend/data/agvdb.mv.db`，重启不丢数据。
- 首次启动会自动建表，并写入演示数据：2 个账号、2 套路网模板、1 个 20 单的任务集、算法/指标字典。
- 想清空重来：`Ctrl+C` 停掉后端，删除 `agv-backend/data/`，再启动。
- **这个终端不要关**，关掉后端就停了。

## 6. 启动前端（终端 B）

**再开一个终端**：

```powershell
cd agv-frontend
npm install
npm run dev
```

`npm install` 只有第一次需要（已有 `node_modules` 可跳过）。启动成功会看到：

```
VITE v5.4.x  ready in 512 ms

➜  Local:   http://localhost:5173/
```

浏览器打开 <http://localhost:5173>，应该看到「排策智演」的登录页。

说明：

- 前端不需要你手工配置后端地址。`vite.config.ts` 里已经配好代理：`/api` 和 `/ws` 都转发到 `http://localhost:8080`。
- 如果 5173 被别的程序占用，Vite 会自动换到 5174，**以终端打印的地址为准**。
- 前端终端也别关。

## 7. 冒烟验证：30 秒确认三条链路都通

1. 登录页的用户名/密码已经预填 `admin` / `admin123`，直接点「登录」。
2. 进入「概览」页，看到「路网」卡片显示 **2**，下面小字「含预置模板 2 套」。
3. 找到「WebSocket 连通性自检」面板：点「连接」，标签变成「已连接」；再点「发送 ping」，下方出现两行消息，类似：
   - `{"type":"connected","sessionId":"..."}`
   - `{"type":"echo","payload":"ping-1762..."}`

这三步分别证明：

| 看到的现象 | 证明了什么 |
|---|---|
| 登录页能打开、能跳转 | 前端页面和路由正常 |
| 概览能读到路网数量 | 登录鉴权 + REST 接口正常（token 存在 localStorage） |
| WebSocket 能连上并收到 echo | `/ws` 代理和帧通道正常 |

如果第 2 步路网是 0，或第 3 步连不上，看第 10 节。

## 8. 完整业务演示（约 10 分钟）

先一句话理解这个系统：车间里有多台 AGV，按任务集把货从 A 工位运到 B 工位；系统用 A\* 算路径、用时间窗避免撞车，前端 3D 实时显示小车运动和冲突等待。

### 8.1 看一眼车间地图

左侧菜单「车间地图」→ 点列表里的「标准车间（双充电位）」。

预期：右侧画布出现节点和路段（工位、充电位、路口），左侧显示「X 节点 · Y 路段」。点「校验」，提示通过。

这些模板对普通账号是只读的；用 `admin` 登录可以直接改，但建议先点「另存为」另存一份，避免动到演示数据。这一步不改也能继续。

（可选）试着拖动节点，或在空白处框选多个节点后一起拖动；滚轮缩放，按住空格拖动画布。新增节点要先在工具栏选择「工位/充电位/缓存位/路口」，再单击空白处。改完点「校验」看规则是否通过，完整操作见 [编辑车间地图](../how-to/编辑车间地图.md)。

### 8.2 看一眼任务集

左侧菜单「任务集」→ 列表里有一个预置任务集（20 单）。点「编辑」能看到每条任务的起点/终点（W1/W2/W3 之间循环）。

不需要修改，关掉弹窗即可。

### 8.3 跑一次仿真

左侧菜单「仿真运行」。工具栏按下面设置：

| 参数 | 值 |
|---|---|
| 路网 | 标准车间（双充电位） |
| 任务集 | 预置任务集 |
| 算法 | 就近分配 |
| AGV 数量 | 3 |
| 随机种子 | 20261107（默认，先别改，保证结果可复现） |

点「开始」。预期：

- 左边 3D 场景里出现 3 台小车并开始移动；
- 右侧指标 `tick` 持续递增，「完成」从 `0/20` 走到 `20/20`，进度条走满；
- 「车辆状态」里能看到 空闲 / 行驶 / 等待 / 装卸 / 充电；
- 「事件日志」陆续出现 分配任务、装货、冲突等待、任务完成。

可以顺手试「暂停」「继续」「0.5x～4x」「重置」。

### 8.4 做一次算法对比

左侧菜单「对比实验」→ 保持默认参数（同一路网、同一任务集、3 台 AGV、种子 20261107）→ 点「运行对比（两种算法）」。

预期：

- 「指标对比」表出现两行：就近分配、贪心 ETA；
- 下方柱状图同时展示 完成时间 / 总路径长 / 总等待 / 冲突次数 四项指标；
- 「我的历史实验」多出两条记录，换种子再跑还会继续累积。

到这里，你已经完整走完「改参数 → 跑仿真 → 看指标 → 存历史」的闭环，这也是论文第 6 章数据的来源。

## 9. 停止、再次启动、一键脚本

**停止**（任选其一）：

- 两个终端分别按 `Ctrl+C`；
- 或在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop-dev.ps1
```

后者会直接结束占用 8080 / 5173 的进程，适合后台窗口找不到的情况。

**再次启动**：只需要第 5、6 步，**不用再 `mvn install`**（除非你改了 `agv-algorithm` 的代码或 `pom.xml`）。

**一键脚本**：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\dev.ps1
```

它做三件事：根目录 `mvn -DskipTests install` → 开两个 PowerShell 窗口分别起后端和前端 → 打印地址和账号。脚本只等 12 秒就启动前端，首次后端可能还没就绪，刷新一下页面即可。

**重置演示数据**：停掉后端，删除 `agv-backend/data/`，再启动。

## 10. 常见问题（只列会挡住你的）

| 现象 | 原因 | 处理 |
|---|---|---|
| `Could not resolve dependencies ... com.agv:agv-algorithm:1.0.0` | 没在根目录 install | 回第 4 步，执行 `mvn -DskipTests install` |
| `'mvn' 不是内部或外部命令` | Maven 没装或没进 PATH | 重开终端；`mvn -v` 自查 |
| `release version 17 not supported` / `无效的目标发行版: 17` | Maven 用的是 JDK 8/11 | `mvn -v` 看 `Java version`，把 `JAVA_HOME` 指向 JDK 17 |
| `Port 8080 was already in use` | 旧后端没停 | `scripts\stop-dev.ps1`，或只保留一个后端进程 |
| 5173 打不开 | 前端没起或换了端口 | 看终端打印的 `Local:` 地址 |
| 页面能开，但提示「网络异常」/ 登录报错 | 后端没起，或不在 8080 | 先访问 `http://localhost:8080/api/health` |
| 登录后立刻被踢回登录页 | token 过期（默认 12 小时） | 重新登录 |
| `npm install` 卡住 / 证书错误 | 网络或 registry 问题 | `npm config set registry https://registry.npmmirror.com` 后重试 |
| H2 报 `Database may be already in use` | 已有后端实例占用数据文件 | 关掉多余的后端进程，只留一个 |
| Windows 控制台中文乱码 | 终端编码不是 UTF-8 | 用 `scripts\dev.ps1`（已设 UTF-8），或先 `chcp 65001` |
