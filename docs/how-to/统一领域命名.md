# 如何统一领域命名

> 状态：**Phase 0–3 已完成；Phase 4 计划中**。
> 术语以 [领域模型与术语](../reference/领域模型与术语.md) 为准。本文解决的是「代码、接口、页面、论文叫法不一致」的问题。

## 1. 适用场景

- 读代码时发现 `RoadNetEntity`、`RoadNet`、「车间地图」指向同一概念。
- 想在论文或答辩里统一用「路网」，但不确定该改哪一层。
- 需要确认 `mapId` 改成 `roadnetId` 后，数据库列、接口和前端还剩哪些历史名。

## 2. 前置条件

- 已阅读 [领域模型与术语](../reference/领域模型与术语.md) 的「已知别名」。
- 工作区干净，当前分支可随时回滚。
- 后端测试、前端类型检查和地图回归都能跑通。

```powershell
mvn test
cd agv-frontend
npm run type-check
npm run e2e:roadnet
cd ..
```

## 3. 现状与目标

| 当前 | 含义 | 目标 | 所在层 |
|---|---|---|---|
| `RoadNetEntity`（原 `WarehouseMap`） | 路网持久化实体 | 保持 | 后端实体 |
| `RoadNetRepository`（原 `WarehouseMapRepository`） | 路网仓储 | 保持 | 后端仓储 |
| `roadnet`（原 `warehouse_map`） | 路网表 | 保持 | 数据库 |
| `roadnetId`（原 `mapId`） | 任务集/实验绑定的路网 ID | 保持 | API、前端、服务 |
| `roadnet_id`（原 `map_id`） | 外键列 | 保持 | 数据库 |
| 车间地图 | 路网编辑页 | 路网（或保留页面名） | 前端文案 |
| `roadnet_json` | 路网整图 JSON | 保留 | 数据库 |

原则：**先改内部、再改接口、最后改数据库**。每一步都能单独回滚。

## 4. Phase 0：记录别名，不改代码

已完成。见 [领域模型与术语](../reference/领域模型与术语.md) 第 8 节。

本阶段只建立共识：`WarehouseMap` 是历史持久化名字，`RoadNet` 是领域名字，两者不是两个模型。实体现已改名为 `RoadNetEntity`。

## 5. Phase 1：重命名后端内部类（已完成）

### 改什么

- `agv-backend/src/main/java/com/agv/backend/entity/WarehouseMap.java` → `RoadNetEntity.java`
- `agv-backend/src/main/java/com/agv/backend/repository/WarehouseMapRepository.java` → `RoadNetRepository.java`
- 更新 `RoadNetService`、`TaskSetService`、`DataInitializer` 和测试中的引用。

### 不改什么

- 保留 `@Table(name = "warehouse_map")`（Phase 3 已改 `roadnet`）。
- 保留 `@Column(name = "roadnet_json")`。
- 保留实体字段 `mapId` 和 API JSON 字段 `mapId`（Phase 2 才改）。

这样数据库和接口都不变，只改读者看到的类名。

### 验证

```powershell
git grep -n "WarehouseMap" -- agv-backend
mvn test
```

`git grep` 只应命中历史文档或迁移说明，不应命中 `src/main/java`。

### 提交

```text

```

## 6. Phase 2：API 从 `mapId` 改为 `roadnetId`（已完成）

> 实际结果：API JSON、前端字段和服务属性已统一为 `roadnetId`，`TaskSetSummary.mapName` 同步改为 `roadnetName`；Phase 2 时数据库列仍保留 `map_id`，Phase 3 已改为 `roadnet_id`；未添加 `@JsonAlias` 兼容。

### 改什么

后端：

- `TaskSet.mapId` → `roadnetId`，Phase 2 保留 `@Column(name = "map_id")`，Phase 3 已改 `roadnet_id`。
- `Experiment.mapId` → `roadnetId`，Phase 2 保留 `@Column(name = "map_id")`，Phase 3 已改 `roadnet_id`。
- DTO 记录字段改名：
  - `TaskSetSummary.mapId`
  - `SaveTaskSetRequest.mapId`
  - `ExperimentReport.mapId`
  - `ExperimentRequest.mapId`
  - `StartSimRequest.mapId`
- Controller 查询参数：`@RequestParam Long mapId` → `roadnetId`。
- Repository 派生查询：`findByMapId...` → `findByRoadnetId...`、`countByMapId` → `countByRoadnetId`。
- `SimulationService.statusPayload()` 里的 `mapId` 键。

前端：

- `agv-frontend/src/api/sim.ts` 中所有 `mapId` 字段和 `mapId` 查询参数。
- `TaskSetView.vue`、`RoadNetView.vue`、`SimulationView.vue`、`ExperimentView.vue` 中的 `mapId` 变量和表格列。
- 表格列 `prop="mapId"` 改为 `prop="roadnetId"`；显示名仍可为「路网」。

文档：

- README 的 API 示例。
- `docs/how-to/维护任务集.md` 中出现的请求体字段。
- `paper/thesis` 中的接口表和复现参数。

### 兼容策略

这是一个前后端同步发布的内部系统，默认不保留旧字段。如果确实需要兼容旧客户端：

```java
public record ExperimentRequest(
        @JsonAlias("mapId") Long roadnetId,
        Long taskSetId,
        String algorithm,
        Integer agvCount,
        Long seed) {
}
```

兼容别名只保留一个版本，下一轮删除。

## 7. Phase 3：数据库表与列改名（已完成）

> 实际执行：本地 H2 库已迁移，迁移前后 3 张路网、1 个任务集、129 条实验记录；表 `roadnet`、列 `roadnet_id` 已生效，Hibernate 未再生成 `warehouse_map`。迁移脚本见 [scripts/migrate-roadnet-naming.sql](../../scripts/migrate-roadnet-naming.sql)。
>
> MySQL 环境仍需按同一脚本手动执行，执行前先备份。

现状：`spring.jpa.hibernate.ddl-auto=update` 只会新增列/表，**不会重命名**。直接改 `@Table` / `@Column` 会留下旧表旧列，甚至让旧数据不可见。

### 迁移步骤

1. 备份数据库：
   - H2：停止后端，复制 `agv-backend/data/agvdb.mv.db`。
   - MySQL：`mysqldump agv_sim > backup.sql`。
2. 执行迁移 SQL（完整脚本见 `scripts/migrate-roadnet-naming.sql`）：

```sql
ALTER TABLE warehouse_map RENAME TO roadnet;
ALTER TABLE task_set RENAME COLUMN map_id TO roadnet_id;
ALTER TABLE experiment RENAME COLUMN map_id TO roadnet_id;
```

3. 再改实体：

```java
@Table(name = "roadnet")
@Column(name = "roadnet_id")
```

4. 启动后端，确认 Hibernate 不再生成旧表，数据条数一致。

### 验证

```powershell
mvn test
```

并手工检查：

- 路网列表数量与迁移前一致。
- 任务集绑定的路网 ID 没变。
- 实验历史还能查到指标。
- 地图保存、任务集保存、仿真、实验各跑一次。

### 回滚

- 代码：`git revert`。
- 数据库：恢复备份文件或反向执行 `RENAME`。

### 提交

```text
refactor(db): rename warehouse map table
```

**执行结果**：本地 H2 已完成迁移并通过接口验证；新环境直接由 Hibernate 按新注解建表。MySQL 环境按脚本手动执行一次。

## 8. Phase 4：页面文案（低风险，建议保留）

建议：

- 菜单和页面标题继续叫「车间地图」。
- 在术语文档中声明「车间地图 = 路网编辑页」。
- 如果一定要改，只改页面副标题或 tooltip，例如「车间地图（路网）」，不改路由和菜单。

如果要全量改名，需要同步：
