# 如何统一领域命名

> 状态：**Phase 0、Phase 1 已完成；Phase 2–4 计划中**。
> 术语以 [领域模型与术语](../reference/领域模型与术语.md) 为准。本文解决的是「代码、接口、页面、论文叫法不一致」的问题。

## 1. 适用场景

- 读代码时发现 `WarehouseMap`、`RoadNet`、「车间地图」指向同一概念。
- 想在论文或答辩里统一用「路网」，但不确定该改哪一层。
- 准备把 `mapId` 改成 `roadnetId`，担心影响接口、数据库或前端。

## 2. 前置条件

- 已阅读 [领域模型与术语](../reference/领域模型与术语.md) 的「已知别名」。
- 工作区干净，当前分支可随时回滚。
- 后端测试、前端类型检查和地图回归都能跑通。

```powershell
mvn test
cd agv-frontend
npm run type-check
npm run e2e:roadnet
cd ..
```

## 3. 现状与目标

| 当前 | 含义 | 目标 | 所在层 |
|---|---|---|---|
| `RoadNetEntity`（原 `WarehouseMap`） | 路网持久化实体 | 保持 | 后端实体 |
| `RoadNetRepository`（原 `WarehouseMapRepository`） | 路网仓储 | 保持 | 后端仓储 |
| `warehouse_map` | 路网表 | `roadnet` | 数据库 |
| `mapId` | 任务集/实验绑定的路网 ID | `roadnetId` | API、前端、服务 |
| `map_id` | 外键列 | `roadnet_id` | 数据库 |
| 车间地图 | 路网编辑页 | 路网（或保留页面名） | 前端文案 |
| `roadnet_json` | 路网整图 JSON | 保留 | 数据库 |

原则：**先改内部、再改接口、最后改数据库**。每一步都能单独回滚。

## 4. Phase 0：记录别名，不改代码

已完成。见 [领域模型与术语](../reference/领域模型与术语.md) 第 8 节。

本阶段只建立共识：`WarehouseMap` 是持久化名字，`RoadNet` 是领域名字，两者不是两个模型。

## 5. Phase 1：重命名后端内部类（已完成）

### 改什么

- `agv-backend/src/main/java/com/agv/backend/entity/WarehouseMap.java` → `RoadNetEntity.java`
- `agv-backend/src/main/java/com/agv/backend/repository/WarehouseMapRepository.java` → `RoadNetRepository.java`
- 更新 `RoadNetService`、`TaskSetService`、`DataInitializer` 和测试中的引用。

### 不改什么

- 保留 `@Table(name = "warehouse_map")`。
- 保留 `@Column(name = "roadnet_json")`。
- 保留实体字段 `mapId` 和 API JSON 字段 `mapId`。

这样数据库和接口都不变，只改读者看到的类名。

### 验证

```powershell
rg -n "WarehouseMap" agv-backend
mvn test
```

`rg` 只应命中历史文档或迁移说明，不应命中 `src/main/java`。

### 提交

```text
refactor(roadnet): rename warehouse map entity
```

## 6. Phase 2：API 从 `mapId` 改为 `roadnetId`（中风险）

### 改什么

后端：

- `TaskSet.mapId` → `roadnetId`，保留 `@Column(name = "map_id")`。
- `Experiment.mapId` → `roadnetId`，保留 `@Column(name = "map_id")`。
- DTO 记录字段改名：
  - `TaskSetSummary.mapId`
  - `SaveTaskSetRequest.mapId`
  - `ExperimentReport.mapId`
  - `ExperimentRequest.mapId`
  - `StartSimRequest.mapId`
- Controller 查询参数：`@RequestParam Long mapId` → `roadnetId`。
- Repository 派生查询：`findByMapId...` → `findByRoadnetId...`、`countByMapId` → `countByRoadnetId`。
- `SimulationService.statusPayload()` 里的 `mapId` 键。

前端：

- `agv-frontend/src/api/sim.ts` 中所有 `mapId` 字段和 `mapId` 查询参数。
- `TaskSetView.vue`、`RoadNetView.vue`、`SimulationView.vue`、`ExperimentView.vue` 中的 `mapId` 变量和表格列。
- 表格列 `prop="mapId"` 改为 `prop="roadnetId"`；显示名仍可为「路网」。

文档：

- README 的 API 示例。
- `docs/how-to/维护任务集.md` 中出现的请求体字段。

### 兼容策略

这是一个前后端同步发布的内部系统，默认不保留旧字段。如果确实需要兼容旧客户端：

```java
public record ExperimentRequest(
        @JsonAlias("mapId") Long roadnetId,
        Long taskSetId,
        String algorithm,
        Integer agvCount,
        Long seed) {
}
```

兼容别名只保留一个版本，下一轮删除。

### 验证

```powershell
rg -n "\bmapId\b" agv-backend/src/main agv-backend/src/test agv-frontend/src
mvn test
cd agv-frontend
npm run type-check
npm run e2e:roadnet
cd ..
```

还要手工确认：

- 新建/编辑任务集时，绑定路网仍能保存。
- 仿真启动请求能拿到正确的路网。
- 实验历史列表的「路网」列显示正常。

### 提交

```text
refactor(roadnet): rename mapId to roadnetId in API
```

## 7. Phase 3：数据库表与列改名（高风险，暂不执行）

现状：`spring.jpa.hibernate.ddl-auto=update` 只会新增列/表，**不会重命名**。直接改 `@Table` / `@Column` 会留下旧表旧列，甚至让旧数据不可见。

### 迁移步骤

1. 备份数据库：
   - H2：停止后端，复制 `agv-backend/data/agvdb.mv.db`。
   - MySQL：`mysqldump agv_sim > backup.sql`。
2. 执行迁移 SQL：

```sql
ALTER TABLE warehouse_map RENAME TO roadnet;
ALTER TABLE task_set RENAME COLUMN map_id TO roadnet_id;
ALTER TABLE experiment RENAME COLUMN map_id TO roadnet_id;
```

3. 再改实体：

```java
@Table(name = "roadnet")
@Column(name = "roadnet_id")
```

4. 启动后端，确认 Hibernate 不再生成旧表，数据条数一致。

### 验证

```powershell
mvn test
```

并手工检查：

- 路网列表数量与迁移前一致。
- 任务集绑定的路网 ID 没变。
- 实验历史还能查到指标。
- 地图保存、任务集保存、仿真、实验各跑一次。

### 回滚

- 代码：`git revert`。
- 数据库：恢复备份文件或反向执行 `RENAME`。

### 提交

```text
refactor(db): rename warehouse map table
```

**建议**：毕业设计阶段不做 Phase 3。表名不影响功能，风险和收益不成比例。

## 8. Phase 4：页面文案（低风险，建议保留）

用户可见的「车间地图」已经进入 README、操作指南、论文截图和答辩稿。改成「路网」会带来一轮文档和截图返工。

建议：

- 菜单和页面标题继续叫「车间地图」。
- 在术语文档中声明「车间地图 = 路网编辑页」。
- 如果一定要改，只改页面副标题或 tooltip，例如「车间地图（路网）」，不改路由和菜单。

如果要全量改名，需要同步：

- `router/index.ts` 的 `meta.title`
- `LayoutView.vue` 的菜单
- 页面 `<h2>`
- `docs/how-to/编辑车间地图.md`
- 论文中的界面截图和文字

## 9. 执行顺序与提交

```text
docs(domain): add ubiquitous language and context model   ← 已完成
docs(domain): add domain naming migration plan             ← 已完成
refactor(roadnet): rename warehouse map entity             ← Phase 1，已完成
refactor(roadnet): rename mapId to roadnetId in API        ← Phase 2
refactor(db): rename warehouse map table                   ← Phase 3（可选）
```

每个 Phase 单独提交、单独回滚。Phase 1 之前不需要再改文档；Phase 2 之前先改本文和 README 的字段示例；Phase 3 之前先补迁移 SQL 和备份说明。
