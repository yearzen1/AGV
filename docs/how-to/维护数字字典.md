# 维护数字字典

## 适用场景

你是管理员，需要调整系统下拉框里显示的中文名、排列顺序，或临时停用某个选项。

数字字典只承担**显示层**职责：它决定「看到什么文字、按什么顺序、是否出现」，不决定「这个选项背后执行什么逻辑」。

## 前置条件

- 账号角色为 `admin`（预置账号 `admin / admin123`）。
- 后端已启动。首次启动时 `DataInitializer` 会写入两组种子数据：`algorithm`（调度算法）与 `metric`（评价指标）。
- 两个菜单项「用户管理」与「数字字典」只对管理员渲染，接口层同样有 `@PreAuthorize("hasRole('ADMIN')")` 校验。

## 步骤

1. 登录后进入左侧菜单「数字字典」。
2. 在顶部下拉框选择字典类型：**调度算法** 或 **评价指标**。切换后表格重新加载。
3. 在表格中找到目标行，点击「编辑」。
4. 修改其中可编辑的字段（见下表），点击「保存」。
5. 列表自动刷新，状态标签随之更新。

| 字段 | 含义 | 是否可改 |
|---|---|---|
| 编码 `dictCode` | 程序内部识别用的代号，如 `nearest` | 否，只读 |
| 显示名 `dictValue` | 下拉框里显示的文字，如「就近分配」 | 是 |
| 排序 `sort` | 下拉框内的升序位置，数字小的在前 | 是 |
| 状态 `status` | `启用` 出现在下拉框；`停用` 保留数据但不展示 | 是 |

删除入口在每行的「删除」按钮，二次确认后生效。删除不可恢复，**建议优先使用「停用」**。

## 验证

- **调度算法**：回到「仿真运行」，展开算法下拉框。应看到新的显示名、按 `sort` 升序排列，已停用的算法不再出现。
- **评价指标**：修改后实验页不会变化，原因见下一节。

## 常见问题

### 为什么没有「新增」按钮

编码不是纯文案，它同时是后端的分发键：

- `StartSimRequest` / `ExperimentRequest` 用 `@Pattern("nearest|greedy-eta")` 限定取值；
- `TaskAssigners.of(code)` 按编码映射到具体实现，未知编码抛 `IllegalArgumentException`。

所以凭空新增一个编码，只会让下拉框多出一个一点运行就报错的选项。新增算法必须在 `agv-algorithm` 模块写 `TaskAssigner` 实现并注册到 `TaskAssigners`，再同步白名单。字典不承担算法扩展职责。

### 改了「评价指标」为什么界面没变化

实验页的指标名与表头目前由前端与 `ExperimentService` 硬编码，`metric` 组字典是预留数据，尚未接入。这类修改只会落在数据库里，不影响现有页面。

### 删除字典项会影响历史实验吗

不会。历史实验保存的是算法编码，显示名由代码内映射得出，删除字典项不改变已有实验记录。但如果删除的是仍在使用的算法编码，仿真页将无法再选择该算法。

### 停用和删除怎么选

优先停用。停用只是从下拉框隐藏，数据保留，随时可以改回启用；删除是物理删除，只能重新建库或手工插回。
