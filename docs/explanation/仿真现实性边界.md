# 仿真现实性边界

> 说明仿真引擎“模拟了什么、简化了什么、为什么”，以及 P1 修复后的真实状态。
> 事件字段见 [仿真事件与日志](../reference/仿真事件与日志.md)，指标口径见 [领域模型与术语](../reference/领域模型与术语.md)。

## 1. 为什么需要这份说明

“20 单全部完成”只证明调度和预约能收敛，不证明车辆在物理上可行。当前模型是**离散时间步 + 弧段预约**的调度仿真，不是刚体运动仿真。把已建模与未建模分开，才能避免把实验结果当成物理验证。

## 2. 已建模

| 能力 | 当前实现 |
|---|---|
| 时间推进 | 固定 100 ms/tick，单线程、给定参数可复现 |
| 路径规划 | 有向弧上的 A*，支持禁行边绕行 |
| 冲突消解 | 弧级时间窗预约、单车道边互斥、节点容量、优先级让行 |
| 装卸 | 装货 5 tick、卸货 5 tick，均占用车辆状态与工位 |
| 僵局处理 | 连续等待 30 tick 触发绕行；检测等待环后尝试倒车 |
| 回充 | 任务完成后回最近可用充电位停靠 |
| 结束 | 全部任务完成且全部归位；或回充宽限期 1200 tick 到期 |

## 3. 未建模（已知边界）

| 现象 | 当前真实行为 | 现实偏差 | 计划 |
|---|---|---|---|
| 非路口节点容量 | 等待中的车释放节点预约，但人仍停在原地 | 工位/缓存位容量为 1 时，实测最多 5 台车同点 | P2 停线等待 |
| 路口互斥 | 倒车不可行时“逻辑让行”，直接释放路口预约 | 实测路口出现两台车同占，属于碰撞级问题 | P2 取消逻辑让行，改为如实标记死锁 |
| 电量与充电 | 没有电量字段；`CHARGING` 只表示停靠，充电时长不建模 | 车辆不会因缺电中断任务，也不需要排队充电 | P3 |
| 加减速与转向 | 弧内匀速，转向在节点瞬时完成 | 实测每个 tick 位移恒为 0.1000 m，单轮 32–55 次 ≥45° 瞬时转向 | P3 |
| 任务到达 | 任务集在 tick 0 全部就绪 | 没有陆续到达、截止时间或优先级 | P3 |
| 充电位物理形态 | 充电位是“点”，模板容量 4 | 3 台车时 CH1 停 2 台，6 台车时两个位各停 3 台 | P3 |
| 排队空间 | 没有实体队列，等待车占用节点或路段 | 高负载时拥堵表现为节点叠车，而不是排队长度 | P2 |

P1 只修“卸货耗时、最长等待口径、双车道演示数据、结束标注”，**不改变上述物理约束**。

## 4. 对指标的影响

- `makespan`、`totalWaitTick`、`conflictCount` 反映的是调度层代价，不是物理时间或碰撞次数。
- P1 把卸货从 0 改为 5 tick，20 单场景的 `makespan` 至少增加约 100 tick，并可能改变调度顺序；P1 之前产出的实验数据不能与之后的数据混用。
- `maxBlockedTicks` 表示“从进入等待到真正进入下一段”的最长完整阻塞段，跨多次重规划累计；旧字段 `maxWaitTicks` 会因重规划清零，实测可把 1030 tick 的等待误报成 29 tick。

## 5. 如何验证

- 单元测试固定装货/卸货时序、事件顺序与阻塞累计口径。
- 三张模板 × 3/6 台车 × 两种算法的压力跑批用于抽查物理不变量；P1 后路口同占与节点叠车仍会出现，属于本文明示的已知边界。
- 论文第 6 章的“模型边界”小节与本文保持一致；修复 P2 时先改本文，再改代码。
