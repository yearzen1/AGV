# 仿真现实性边界

> 说明仿真引擎“模拟了什么、简化了什么、为什么”，以及 P2 修复后的真实状态。
> 事件字段见 [仿真事件与日志](../reference/仿真事件与日志.md)，指标口径见 [领域模型与术语](../reference/领域模型与术语.md)。

## 1. 为什么需要这份说明

“20 单全部完成”只证明调度和预约能收敛，不证明车辆在物理上可行。当前模型是**离散时间步 + 弧段预约**的调度仿真，不是刚体运动仿真。把已建模与未建模分开，才能避免把实验结果当成物理验证。

## 2. 已建模

| 能力 | 当前实现 |
|---|---|
| 时间推进 | 固定 100 ms/tick，单线程、给定参数可复现 |
| 路径规划 | 有向弧上的 A*，支持禁行边绕行 |
| 冲突消解 | 弧级时间窗预约、单车道边互斥、节点容量、优先级让行 |
| 等待位置 | **停线等待**：不能进入下一节点时停在当前弧末端，不占用目标节点 |
| 路口通行 | **不占箱**：进入路口前同时检查路口和下一段弧，进不去就停在路口前 |
| 装卸 | 装货 5 tick、卸货 5 tick，均占用车辆状态与工位 |
| 僵局处理 | 连续等待 30 tick 触发绕行；检测等待环后尝试真实倒车让行 |
| 死锁 | 全部车辆连续等待 2000 tick 仍未推进时判定 `DEADLOCK`，如实停止并记录，不做非物理让行 |
| 回充 | 任务完成后回最近可用充电位停靠 |
| 结束 | 全部任务完成且全部归位；或回充宽限期 1200 tick 到期 |

## 3. 未建模（已知边界）

| 现象 | 当前真实行为 | 现实偏差 | 计划 |
|---|---|---|---|
| 电量与充电 | 没有电量字段；`CHARGING` 只表示停靠，充电时长不建模 | 车辆不会因缺电中断任务，也不需要排队充电 | 后续 |
| 加减速与转向 | 弧内匀速，转向在节点瞬时完成 | 每个 tick 位移恒定，单轮数十次瞬时转向 | 后续 |
| 任务到达 | 任务集在 tick 0 全部就绪 | 没有陆续到达、截止时间或优先级 | 后续 |
| 充电位物理形态 | 充电位是“点”，模板容量 4 | 多台车停在同一坐标 | 后续 |
| 物理尺寸与传感 | 没有车长、载重、转弯半径、避障传感器 | 预约按弧与点计算，不检查扫掠体积 | 后续 |
| 队列空间 | 等待车停在路段上，会阻塞后车 | 排队长度受路段长度隐式限制，没有专用等待区 | 可接受 |

P2 之后，工位容量与路口互斥在模型内被强制；不再存在“释放预约但车没动”的非物理动作。

## 4. 对指标的影响

- `makespan`、`totalWaitTick`、`conflictCount` 反映的是调度层代价，不是物理时间或碰撞次数。
- P1 把卸货从 0 改为 5 tick；P2 把等待位置从节点内改到停线，并取消了逻辑让行。两次改动都会改变 `makespan`、等待与冲突，P2 之前的数据不能与之后的数据混用。
- `maxBlockedTicks` 表示“从进入等待到真正进入下一段”的最长完整阻塞段，跨多次重规划累计。
- `DEADLOCK` 实验没有完整的任务指标，不参与规模对比；遇到时应减少车辆、调整任务分布或补充让行位。

## 5. 如何验证

- 不变量测试：任意 tick 任意节点上的车数不超过 `capacity`；单车道边不出现正反两向同时占用；不再存在 `LOGICAL_YIELD` 事件，无法解开的等待环标记为 `DEADLOCK`。
- 死锁测试：构造无法解开的等待环，断言引擎在有限 tick 内标记 `DEADLOCK`，而不是互相穿透或无限运行。
- 三张模板 × 3/6 台车 × 两种算法的压力跑批用于抽查上述不变量。
