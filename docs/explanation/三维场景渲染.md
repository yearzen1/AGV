# 三维场景渲染

> 本文解释「为什么这样画」。术语定义见 [领域模型与术语](../reference/领域模型与术语.md)，操作步骤见 [如何运行仿真](../how-to/运行仿真.md)。
> 读者是想改 `RoadNetScene`、调画面表现，或要在论文/答辩里解释可视化实现的人。

## 1. 问题背景

同一张路网有两个视图：二维编辑器负责建模，三维场景负责演示仿真。三维场景只消费后端已经算好的结果，不参与路径规划、预约和冲突判定。这条边界决定了三个设计取舍：

- **比例必须来自路网**：地面、网格、雾、相机远近都按节点包围盒计算，不能用固定的 200 米网格。标准车间只有 16×14 米，固定网格会让车看起来像蚂蚁。
- **运动必须按时间插值**：后端一帧是一个 tick（默认 100ms），倍速越高推送越稀；如果直接「每帧追目标点」，60Hz 和 144Hz 屏幕上的速度会不一样。
- **表现不能反过来影响算法**：视觉上把双车道的车画在各自车道，只是偏移渲染，预约表仍然按算法层的弧和容量计算。

## 2. 坐标系与比例

二维路网的 `x`/`y` 单位是米，直接映射到 three.js 的 `x`/`z`，`y` 轴向上：

| 二维 | 三维 | 说明 |
|---|---|---|
| `node.x` | `x` | 不变 |
| `node.y` | `z` | 二维的「上」在三维是「深度」 |
| `heading`（度，0–360） | `rotation.y = -heading` | 绕 Y 轴反向旋转才能让模型车头对准二维朝向 |

场景里的固定尺寸：

| 对象 | 尺寸（米） | 依据 |
|---|---|---|
| AGV 车身 | 1.5 × 1.0 | 与节点间距（4–10 米）保持真实比例 |
| 单条车道宽 | 1.3 | 车身 1.0 米宽，两侧各留 0.15 米余量 |
| 双车道中心偏移 | ±0.7 | 两条车道相距 1.4 米，中间留出分隔带 |
| 工位地台边长 | 2.4 | 略宽于双车道路面，路口不露出路肩 |
| 充电位地台半径 | 1.2 | 与充电光环同心 |
| 缓存位地台边长 | 1.8 | 不遮挡相邻车道 |
| 路口地台半径 | 0.9 | 覆盖三条以上车道交汇处 |

场景初始化后，`fitView()` 会按节点包围盒同步更新：地面尺寸（`span × 3`）、网格密度（2 米一格）、雾起止距离（`span × 2.2` 到 `span × 5`）、相机远裁剪面和平行光阴影相机范围。路网跨度不足 10 米时按 10 米计算，避免小图相机贴到地面。

## 3. 时间驱动的帧缓冲插值

后端每推一帧，前端把它连同**到达时间**写入定长队列（最多 60 帧），渲染时取「当前时间 − 120ms」那一时刻做插值：

1. 找到不晚于采样时刻的最后一帧 `a` 和它的下一帧 `b`；
2. 位置按 `(t - a.at) / (b.at - a.at)` 线性插值，朝向按最短角差插值；
3. 状态取 `a` 的状态，保证「车到了才变装卸色」，不会提前跳色；
4. 采样时刻晚于最后一帧时停在最后一帧，不向外推。

这样做的好处：

- 5Hz 推送也能渲染出连续运动；
- 60Hz 与 144Hz 屏幕走过同样的距离；
- 暂停后不再有新帧，画面自动停在最后位置，不会继续滑行。

不采用「每帧 `lerp(target, 0.35)`」的原因：收敛速度取决于帧率，而且朝向直接线性插值会在 ±180° 处绕一圈。朝向统一走 `shortestAngleDelta`，单次转向不超过 180°。

## 4. 视觉车道

`AgvSnapshot.arcId` 形如 `E1+` / `E1-`，后缀就是行驶方向。渲染时：

- 双向 + `DUAL` 路段：`+` 弧靠右行驶，`-` 弧靠自己的右侧（相对物理中心线在另一侧），偏移量 ±0.7 米；
- 双向 + `SINGLE`、单向路段：车辆沿路网中心线，和算法模型一致；
- 车辆停在节点（`arcId` 为空）时偏移目标回落到 0，用指数平滑过渡，避免在路口瞬移。

偏移只改变 `x`/`z` 显示位置，不改变 `AgvSnapshot.s`、不改预约区间、不改冲突判定。论文里描述时也应写成「视觉效果」，不要说成「双车道物理隔离」。

## 5. 真实感的构成

| 手段 | 作用 | 默认档位 |
|---|---|---|
| `ACESFilmicToneMapping` + sRGB 输出 | 高光不糊、颜色不发灰 | 全部 |
| 半球光 + 投影平行光 | 车和地台有落地感 | 中、高 |
| 平行光阴影相机按包围盒拟合 | 阴影边缘清晰，远处不浪费分辨率 | 中、高 |
| 实体路面 + 独立箭头网格 | 替代 1px 线和逐边锥体，箭头长度固定、短路段不被裁切 | 全部 |
| `RoomEnvironment` 环境贴图 | 金属车身有反射 | 中、高 |
| 自发光状态灯 | 等待/充电/装卸一眼可辨 | 全部 |
| `UnrealBloomPass` | 状态灯和充电位产生轻微光晕 | 高 |

性能预算：

- 路段几何按边合并为 1–3 个 `Mesh`（路面、箭头、分隔线各一个），节点按类型使用 `InstancedMesh`；目标是不随边数线性增加 draw call。
- 车辆是独立的可动对象，单车约 9 个 draw call（车身、底盘、车轮、车灯、货箱、状态灯、接触阴影、选择环、标签）。3 台车约 55 个，12 台车约 130 个，仍远低于浏览器瓶颈。
- 标签纹理按「文本 + 颜色」缓存，同一编号在节点和车辆之间复用，场景销毁时统一释放。
- 高画质才创建 `EffectComposer`；切到中/低档时销毁 composer 和渲染目标，避免常驻显存。

## 6. 视角与交互

- **跟随**：相机目标锁定选中的 AGV，保持当前观察距离和角度；用户一旦拖动旋转/平移就自动退出跟随，避免和 OrbitControls 抢控制权。
- **俯视**：相机移动到目标正上方并禁用旋转；退出时恢复可旋转和之前的观察距离。
- **选中**：点击 AGV 时发射 `select` 事件，右侧车辆列表同步高亮；点击空白处取消选中。
- **标签**：节点和车辆编号可整体关闭；标签始终朝向相机，位于车顶上方，开启深度测试避免穿地。

## 7. 有意不做

- **不做后端规划路径预览**：需要给 `SimFrame` 增加路径字段，属于协议变更，单独评估。
- **不引入 GLTF 车辆模型**：几何体组合已经能表达车体、车轮、状态灯和货箱，模型文件会增大打包体积且不利于答辩时解释。
- **不搭装饰性厂房**：路网没有房间、货架元数据，硬加墙体会让画面与真实拓扑不一致。
- **不做车辆物理仿真**：转弯、加减速仍由后端 tick 决定，前端只做表现。

## 8. 验证

- 纯函数单测（`cd agv-frontend && npm test`）覆盖：
  - `lanesForEdge` / `laneOffsetForArc`：双车道拆两条、两条车道分居中心线两侧、单向和单车道回退到中心线；
  - `offsetAlongRight`：同一位置、朝向相反的车落到相反车道，保证车辆和路面用同一套右手规则；
  - `buildRoadGeometry`：DUAL 生成 2 条路面 + 1 条分隔线，单车道双向生成 1 条路面 + 2 个反向箭头，单向不生成分隔线；所有三角形绕序朝上，合并索引不越界。
- 开发模式暴露 `window.__AGV_SCENE_DEBUG__`，内容为 `{ road: { ribbons, dividers, arrows }, agvs: [{ id, arcId, laneOffset }] }`。它只用于端到端断言，生产构建不会写入。
- `cd agv-frontend && npm run e2e:scene`：通过接口创建一张双车道临时路网，打开 3D 预览，按接口数据计算期望的路面/分隔线数量并与场景实际统计对比，截图写到 `.playwright-mcp/e2e/dual-scene.png`，结束后删除临时路网。
- 预置「双车道车间（会车演示）」模板：主环路段为 `DUAL`，用来直接观察对向会车和视觉车道；通往工位、缓存位的分支仍为 `SINGLE`。
