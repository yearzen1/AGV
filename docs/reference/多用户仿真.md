# 多用户仿真

> 本文定义仿真运行态的归属、隔离边界、WebSocket 鉴权与并发上限。
> 术语见 [领域模型与术语](领域模型与术语.md)；为什么这样划分见 [领域模型说明](../explanation/领域模型说明.md)。

## 1. 用途

多个调度人员同时登录时，各自的仿真必须互不干扰：

- 一个人启动、暂停、重置或调速，不能影响别人的仿真；
- 仿真帧只能推给发起人，不能广播给所有连接；
- 单机资源有限，必须有一个并发上限，超限时明确拒绝。

## 2. 归属模型

仿真运行态按**用户**隔离，不按 WebSocket 连接隔离。

| 规则 | 说明 |
|---|---|
| 一个用户同一时刻只有一个仿真 | 再次启动会替换自己的旧仿真，旧实验记为 `ABORTED` |
| 不同用户互不影响 | 各自的引擎、调度线程、实验记录、状态完全独立 |
| 同一用户多个连接 | 打开多个标签页时，每个连接都会收到该用户的帧 |
| 连接断开不停止仿真 | 关闭页面后仿真继续，重新进入页面用 `GET /api/sim/status` 恢复 |
| 仿真运行态在内存 | 只支持单后端实例；多实例需要粘性会话或状态外置 |

不按连接隔离的原因：页面刷新会换一条 WebSocket 连接，按连接隔离会让刷新等同于“丢失仿真”，与现有的状态恢复能力冲突。

## 3. 生命周期

| 操作 | 当前用户没有仿真 | 当前用户有仿真 |
|---|---|---|
| `POST /api/sim/start` | 新建并启动 | 先中止自己的旧仿真，再新建 |
| `POST /api/sim/pause` | 返回 `4004` | `paused = true`，继续保留引擎 |
| `POST /api/sim/resume` | 返回 `4004` | `paused = false` |
| `POST /api/sim/speed` | 返回 `4004` | 调整自己的倍速，范围 0.25–8.0 |
| `POST /api/sim/reset` | 幂等返回 `IDLE` | 停止并移除自己的仿真，实验记为 `ABORTED` |
| `GET /api/sim/status` | 返回 `IDLE` 空状态 | 返回自己的状态、参数、tick、指标与车辆快照 |

`FINISHED` / `FAILED` 的仿真会保留在内存中，供刷新后查看结果；再次启动或重置时释放。

前端在 `RUNNING`（含暂停）期间锁定路网、任务集、算法、AGV 数量与随机种子，避免场景里的车辆和当前参数脱节；倍速只在 `RUNNING` 时可调，`IDLE` / `FINISHED` / `FAILED` 时禁用。重置后倍速回到 `1.0x`。

## 4. 控制接口

接口路径与请求体不变，语义统一变为“当前登录用户”：

```http
POST /api/sim/start    {"roadnetId":1,"taskSetId":1,"algorithm":"nearest","agvCount":3,"seed":20261107}
POST /api/sim/pause
POST /api/sim/resume
POST /api/sim/reset
POST /api/sim/speed?value=2.0
GET  /api/sim/status
Authorization: Bearer <token>
```

返回体仍是状态对象：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "status": "RUNNING",
    "paused": false,
    "speed": 1.0,
    "experimentId": 128,
    "roadnetId": 1,
    "taskSetId": 1,
    "algorithm": "nearest",
    "agvCount": 3,
    "seed": 20261107,
    "tick": 42,
    "metrics": {"makespan": 0, "totalPathLen": 12.3, "totalWaitTick": 0,
                "conflictCount": 0, "completedTasks": 2, "totalTasks": 20},
    "agvs": [
      {"id": "AGV-1", "status": "MOVING", "arcId": "E9", "s": 5.0,
       "x": 12.0, "y": 8.5, "heading": 90.0, "taskId": 1, "waitTicks": 0, "nodeId": "W1"}
    ]
  }
}
```

`agvs` 是当前帧的车辆快照数组，字段与 WebSocket 帧里的 `frame.agvs` 相同：

- `RUNNING` 时返回最后一帧的快照；**暂停期间也返回暂停那一刻的位置**，刷新页面后前端据此恢复 3D 场景里的车辆与「车辆状态」列表，不会退化成「尚未启动仿真」。
- `FINISHED` / `FAILED` / `IDLE` 返回空数组 `[]`。仿真结束后车辆位置不保证可恢复，页面沿用「车辆位置只在运行中可见」的提示。
- 该字段只用于恢复展示，不参与实验指标计算。

## 5. WebSocket 鉴权与路由

浏览器无法给 WebSocket 设置 `Authorization` 头，因此令牌放在查询参数：

```text
ws://localhost:8080/ws/sim?token=<jwt>
```

握手时后端依次做：

1. 解析 JWT；缺失、过期或签名错误 → 返回 401，拒绝握手；
2. 按用户名回查账号，账号不存在或已停用 → 返回 401；
3. 把 `userId` 写入 WebSocket 会话属性，后续只向该用户推送。

连接成功后：

- 服务端先回 `{"type":"connected","sessionId":"..."}`；
- 发送任意文本会收到 `{"type":"echo","payload":"..."}`；
- 仿真帧 `{"type":"frame",...}` 与状态 `{"type":"status",...}` 只发给该用户的会话；
- 仿真自然结束或推进失败时，服务端**先推送** `status = FINISHED` / `FAILED` 的状态消息，**再**停止调度线程，因此结束消息不会被线程中断吞掉，连接保持可用；
- 页面离开「仿真运行」时会主动关闭连接；连接意外断开时前端每 2 秒自动重连，用户也可以点「重连」立即重试。

令牌在握手时校验一次；连接建立后即使令牌过期，已建立的连接仍可继续接收帧，直到主动断开。

## 6. 并发上限

```yaml
agv:
  sim:
    max-concurrent: ${AGV_SIM_MAX_CONCURRENT:5}
```

- 只统计 `RUNNING` 的仿真；`FINISHED` / `FAILED` 不占名额。
- 达到上限时，新的 `start` 返回 `code = 4290` / HTTP 429，消息为“并发仿真数已达上限（N），请稍后再试”。
- 不做排队。被替换或结束的仿真会立即释放名额。
- 默认 5 是按单机 CPU 与 100 ms tick 估算的保守值，可按机器配置调整。

## 7. 与实验记录的关系

- 仿真启动时创建的 `experiment.create_user` 是发起人；
- 每个用户的历史列表只返回自己的实验；
- 强制中止只影响自己的 `RUNNING` 实验，不会误伤其他用户；
- 实验快照、回放规则不变，见 [实验快照与回放](实验快照与回放.md)。

## 8. 错误与边界

| code | HTTP | 场景 |
|---|---|---|
| 4004 | 400 | 当前用户没有运行中的仿真（pause/resume/speed），或仿真参数无法启动 |
| 4010 | 401 | WebSocket 握手没有令牌、令牌过期或无效 |
| 4290 | 429 | 并发仿真数已达上限 |

## 9. 兼容性与迁移

- `/api/sim/*` 的路径与响应结构不变，前端控制代码无需修改。
- WebSocket 连接方式从 `/ws/sim` 变为 `/ws/sim?token=<jwt>`；旧客户端不带令牌会被拒绝。
- `GET /api/sim/status` 从“全局状态”变为“当前用户状态”，多用户下不再互相覆盖。
- 重启后端仍会把遗留的 `RUNNING` 实验标记为 `ABORTED`，与单用户时期一致。
