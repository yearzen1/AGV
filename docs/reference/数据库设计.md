# 数据库设计

> 本文定义持久化表、主键生成策略和数据库迁移规则。
> 表结构以 Flyway 迁移脚本为准，本页说明「为什么这样设计、如何验证」。

## 1. 用途

回答三个问题：

- 系统有哪些表，各存什么；
- 主键是什么类型、由谁生成；
- 已有数据库如何升级或重建。

## 2. 表清单

| 表 | 职责 | 主键 | 迁移脚本 |
|---|---|---|---|
| `sys_user` | 用户、密码哈希、角色、启用状态 | `id` | `V1__init.sql` |
| `sys_dict` | 算法与指标的数字字典 | `id` | `V1__init.sql` |
| `roadnet` | 路网，整图存为 JSON | `id` | `V1__init.sql` |
| `task_set` | 任务集，任务列表存为 JSON，绑定路网 | `id` | `V1__init.sql` |
| `experiment` | 实验头、输入快照、状态 | `id` | `V1__init.sql` |
| `experiment_metric` | 实验四项指标，与实验一对一 | `id` | `V1__init.sql` |
| `sys_audit_log` | 业务审计日志，只追加 | `id` | `V3__audit_log.sql` |

所有表的主键统一为：

```sql
id BIGINT NOT NULL PRIMARY KEY
```

**不使用 `AUTO_INCREMENT` / `IDENTITY`**，数据库只负责存储，不负责发号。

## 3. 主键生成策略

主键由后端应用侧生成，规则为 53 位雪花 ID：

| 位段 | 宽度 | 说明 |
|---|---|---|
| 毫秒时间戳 | 41 位 | 相对 2024-01-01T00:00:00Z 的偏移 |
| worker | 2 位 | 实例编号 0–3，来自 `AGV_WORKER_ID` |
| 序列 | 10 位 | 同一毫秒内递增，溢出后等待下一毫秒 |

合计 41 + 2 + 10 = 53 位，最大值为 `2^53 - 1`，不超过 JavaScript `Number.MAX_SAFE_INTEGER`。因此接口 JSON 里的 `id` 仍然是数字，前端不需要把 Long 转成字符串。

约束：

- 单实例默认 `AGV_WORKER_ID=0`；多实例部署时每个实例必须使用不同值，范围 0–3。
- 同一实例内生成线程安全；检测到系统时钟回拨时直接拒绝生成，避免出现重复 ID。
- 预置数据例外：标准车间固定 `id=1`、直线车间固定 `id=2`、演示任务集固定 `id=1`，用于保持论文与 README 中的复现参数 `roadnetId=1, taskSetId=1` 不变。新建业务数据才使用雪花 ID。

## 4. 代码对应

| 位置 | 作用 |

## 5. 迁移与重建

V1 / V3 脚本定义的是最终结构，主键列不带自增。修改这些脚本后，已应用过旧脚本的数据库会出现 Flyway checksum 不一致，需要重建：

- **H2（开发环境）**：停止后端，备份并移走 `agv-backend/data/agvdb.mv.db`，重启后 Flyway 从 V1 重新建表；`DataInitializer` 会重新写入预置账号、字典、模板和演示任务集。
- **MySQL（论文 / 答辩环境）**：

  ```sql
  DROP DATABASE agv_sim;
  CREATE DATABASE agv_sim DEFAULT CHARSET utf8mb4;
  ```

  然后使用 `mysql` profile 重新启动，Flyway 会自动建表。

## 6. 验证

MySQL：

```sql
SHOW CREATE TABLE experiment;
-- 期望：id BIGINT NOT NULL，且没有 AUTO_INCREMENT
```

H2：

```sql
SELECT table_name, is_identity
FROM information_schema.columns
WHERE column_name = 'id';
-- 期望：7 行，is_identity 全部为 NO
```
