# 仿真事件与日志

> 本文定义仿真运行期间产生的可观测信息：事件流与落库事件、引擎诊断计数、后端摘要日志。
> 术语以 [领域模型与术语](领域模型与术语.md) 为准；回放边界见 [实验快照与回放](实验快照与回放.md)。

## 1. 用途与边界

用于回答“这次仿真过程中发生了什么”，而不是“每个 tick 每台车在哪里”。

| 记录 | 位置 | 持久化 | 用途 |
|---|---|---|---|
| 事件流 `SimEvent` | WebSocket 帧 → 前端「事件日志」 | 运行中否，刷新即丢 | 观察任务、等待、绕行、结束等关键动作 |
| 事件表 `simulation_event` | 实验结束后批量写入 | 是，单实验上限 5000 条 | 历史实验回看、导出 CSV、事后排查 |
| 诊断计数 `SimDiagnostics` | `SimulationEngine.diagnostics()` | 否 | 生成后端摘要日志，量化等待与僵局 |
| 摘要日志 | 后端控制台（INFO） | 仅控制台 | 按 `experimentId` 检索一次仿真的参数、结果与异常计数 |
| 实验指标 | `experiment_metric` 表 | 是 | 只有四项汇总，见第 6 节 |

明确不做：

- 不保存逐帧位置，刷新页面或仿真结束后无法回看车辆轨迹。
- 回放是输入回放（重跑一次复算指标），不是事件溯源；落库事件只能查看，不参与回放。
- 单实验事件超过 5000 条时只保留前 5000 条，接口返回 `truncated=true`。

## 2. 事件模型

`SimEvent` 的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `tick` | `long` | 事件发生的仿真时刻，1 tick = 100ms |
| `agvId` | 字符串 | 相关车辆，如 `AGV-1`；全局事件为 `-` |
| `type` | 枚举 | 见第 3 节 |
| `place` | 字符串 | 相关弧 ID 或节点 ID；无具体位置时为 `-` |
| `detail` | 字符串 | 可直接展示的中文说明 |

同一 tick 可以产生多条事件；事件按发生顺序追加到该 tick 的帧里，前端按“最新在上”展示。

## 3. 事件类型

| 类型 | 触发时机 | `place` | `detail` 格式 |
|---|---|---|---|
| `TASK_ASSIGNED` | 空闲车辆选中一条任务 | 车辆当前节点 | `任务 3：W1 → W2` |
| `LOADING` | 到达取货点，开始装货 | 取货节点 | `开始装货，任务 3` |
| `UNLOADING` | 到达卸货点，开始卸货 | 卸货节点 | `开始卸货，任务 3` |
| `UNLOADED` | 卸货计时结束，计入完成 | 卸货节点 | `卸货完成，耗时 5 tick` |
| `TASK_DONE` | 与本条 `UNLOADED` 同 tick | 卸货节点 | `任务 3 完成` |
| `WAIT_CONFLICT` | 预约失败，车辆从非等待进入等待；一次连续等待只发一次 | 想进入的弧 ID | `路段 E9 已被 AGV-1 占用（相向冲突）`<br>`弧 E9+ 容量已满（追尾冲突）`<br>`节点 W1 被占用（节点冲突）` |
| `WAIT_RESOLVED` | 等待中的车辆成功进入下一段 | 进入的弧 ID | `等待 12 tick 后结束` |
| `REPLAN` | 连续等待达到 `waitTimeoutTicks`（默认 30），带禁行约束重规划成功 | 原计划弧 ID | `等待 30 tick 后绕行重规划，禁行 E9` |
| `DEADLOCK_BREAK` | 检测到等待环 | 争议弧 ID | `检测到等待环，尝试倒车让行` |
| `DEADLOCK_BREAK` | 倒车成功 | 逆向弧 ID | `倒车让行至 J3` |
| `DEADLOCK` | 全部车辆连续等待 2000 tick，或连续 10000 tick 无任务完成 | `-` | `全部车辆连续等待 2000 tick，判定为死锁；等待环：AGV-1@W2 → AGV-4@J2 → AGV-1@W2` |
| `CHARGING` | 回到充电位停靠 | 充电节点 | `停靠充电位（无电量模型，充电时长未建模）` |
| `FINISHED` | 全部任务完成，且全部归位或回充宽限期（1200 tick）到期 | `-` | `全部任务完成，用时 948 tick；归位 3/3 台`<br>`全部任务完成，用时 948 tick；宽限结束，1 台未归位` |

事件与模型现状的对应关系：

- **装货与卸货各 5 tick**。两者分别占用 `LOADING` 与 `UNLOADING` 状态，`UNLOADED` 与 `TASK_DONE` 同 tick 发生。
- **等待发生在停线或节点上**。不能进入下一节点时，车辆停在当前弧末端，不占用目标节点；只有在节点上装卸或回充时才占用节点。
- **充电只表示停靠**。没有电量消耗与充电时长模型，`CHARGING` 只在车辆回到充电位时发出。
- **重规划会结束上一段等待**。`REPLAN` 的 detail 带已等待 tick；之后重新累计，成功进入下一段时才发 `WAIT_RESOLVED`。
- **不再有逻辑让行**。倒车不可行时不会释放路口预约；等待环无法解开时由 `DEADLOCK` 事件标记并停止。
- **死锁详情**。能形成环时输出 `AGV-1@W2 → AGV-4@J2 → AGV-1@W2`，箭头指向下一台阻塞者；无环但无进展时退化为等待最久的三台车及其目标资源。

## 4. 事件序列示例

一次任务从分配到达成，正常路径：

```text
tick 12   AGV-1  任务分配   任务 3：W1 → W2
tick 45   AGV-1  装货       开始装货，任务 3
tick 60   AGV-1  卸货       开始卸货，任务 3
tick 65   AGV-1  卸货       卸货完成，耗时 5 tick
tick 65   AGV-1  任务完成   任务 3 完成
```

发生相向冲突并绕行：

```text
tick 300  AGV-2  冲突等待   路段 E9 已被 AGV-1 占用（相向冲突）
tick 330  AGV-2  重规划     等待 30 tick 后绕行重规划，禁行 E9
tick 352  AGV-2  等待结束   等待 22 tick 后结束
```

检测到等待环：

```text
tick 700  AGV-1  打破僵局   检测到等待环，尝试倒车让行
tick 700  AGV-1  打破僵局   倒车让行至 J3
```

或倒车不可行，进入死锁判定：

```text
tick 700  AGV-1  打破僵局   检测到等待环，尝试倒车让行
tick 2700 -      死锁       全部车辆连续等待 2000 tick，判定为死锁
```

## 5. 诊断计数

`SimulationEngine.diagnostics()` 返回 `SimDiagnostics`，只在后端摘要日志中使用，不进入 WebSocket 帧，也不落库。

| 字段 | 含义 | 口径 |
|---|---|---|
| `replanCount` | 成功发出 `REPLAN` 的次数 | 只统计绕行成功，寻路失败不计 |
| `deadlockBreakCount` | 检测到等待环的次数 | 每次检测到环记 1，与是否倒车成功无关 |
| `retreatSuccessCount` | 倒车让行成功次数 | 每次成功倒车记 1 |
| `maxBlockedTicks` | 单次完整阻塞段的最长 tick | 从进入等待到真正进入下一段，跨重规划累计；让行冷却不计入 |
| `graceFinished` | 是否因回充宽限期到期而结束 | 宽限期 1200 tick，见 `PARK_GRACE_TICKS` |
| `unparkedAtFinish` | 结束时未处于 `CHARGING` / `DONE` 的车辆数 | 宽限结束时通常大于 0 |

`deadlockBreakCount` 只表示检测次数；没有成功倒车的环会在 2000 tick 后进入 `DEADLOCK`，连续 10000 tick 没有任务完成也会进入 `DEADLOCK`。倒车或退回起点成功后会冷却 30 tick，期间不重复尝试。

## 6. 后端摘要日志

每次仿真在控制台输出两行 INFO，异常路径已有 ERROR / WARN：

```text
仿真启动 experimentId=12 user=1 roadnet=1 taskSet=1 algorithm=nearest agv=3 seed=20261107 tasks=20
仿真完成 experimentId=12 tick=1180 makespan=1160 pathLen=412.7 waitTick=63 conflicts=4 replan=2 deadlock=1 retreat=1 grace=false unparked=0 maxBlocked=310 deadlocked=false
```

| 场景 | 日志 |
|---|---|
| 启动 | `SimulationService.start`：参数与任务数 |
| 自然结束 | `SimulationRunner.finish`：四项指标 + 全部诊断计数 |
| 被替换或重置 | `SimulationRunner.stopAndAbort`：`state` 与 `reason` |
| 离线对比实验 | `ExperimentService.runOne`：算法、参数、四项指标、是否完成 |

日志只用于检索与排查，不作为实验数据来源；论文数据以 `experiment_metric` 为准。

## 7. 事件落库与查询

实验结束（`FINISHED` / `FAILED` / `DEADLOCK`）或被重置时，把本次收集到的事件批量写入 `simulation_event`：

| 字段 | 说明 |
|---|---|
| `experiment_id` | 所属实验 |
| `seq_no` | 实验内顺序，从 1 开始 |
| `tick` | 事件发生的仿真时刻 |
| `agv_id` | 相关车辆，全局事件为 `-` |
| `type` | 事件类型 |
| `place` | 相关弧/节点 |
| `detail` | 中文说明，最长 500 字符 |

查询：

```http
GET /api/experiment/{id}/events
Authorization: Bearer <token>
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "events": [
      {"seq": 1, "tick": 12, "agvId": "AGV-1", "type": "TASK_ASSIGNED", "place": "CH1", "detail": "任务 1：W1 → W2"}
    ],
    "truncated": false
  }
}
```

- 只有实验创建人或管理员可查，否则 `4030`。
- 最多返回 5000 条；超出时 `truncated=true`。
- 前端在历史实验的「事件」对话框里展示，并可导出 CSV。

## 8. 现实性判读

| 想确认的问题 | 判读依据 |
|---|---|
| 是否靠倒车解僵局 | 出现 `DEADLOCK_BREAK` 且 detail 为 `倒车让行至 …` |
| 是否出现死锁 | 出现 `DEADLOCK` 事件，或实验状态为 `DEADLOCK`；detail 会给出等待环或等待车列表 |
| 是否等待过久 | `WAIT_RESOLVED` 的 tick 减去对应 `WAIT_CONFLICT` 的 tick；跨重规划时看摘要日志的 `maxBlocked` |
| 是否因停不进充电位而超时结束 | `FINISHED` detail 含“宽限结束”，或摘要日志 `grace=true`、`unparked>0` |
| 是否频繁绕行、路径抖动 | 同一 `agvId` 反复出现 `REPLAN` |
| 卸货是否真的耗时 | `UNLOADING` 与 `UNLOADED` 之间的 tick 差，默认 5 tick |
| 充电是否真的发生 | 没有电量字段；`CHARGING` 只表示停靠 |

## 9. 截断与丢失

| 情况 | 结果 |
|---|---|
| 事件超过 500 条 | 前端只保留最近 500 条，面板显示「仅显示最近 500 条」 |
| 落库事件超过 5000 条 | 只保留前 5000 条，查询接口返回 `truncated=true` |
| 刷新页面或切换菜单 | 事件清空；运行状态与指标通过 `GET /api/sim/status` 恢复 |
| 仿真结束 | 不再推送位置与事件；指标、落库事件与历史实验仍可查 |
| 后端重启 | 内存中的仿真丢失，遗留 `RUNNING` 实验被标记为 `ABORTED`；已落库事件保留 |

实时事件流仍有损；历史实验的事件以落库表为准，但它不包含逐帧位置。

## 10. 兼容性

- 新增事件类型只追加，不修改既有类型的语义；前端未识别的新类型按原始枚举名展示。
- P1 起卸货占用 5 tick，`makespan` 等指标与 P1 之前的数据不可直接比较；事件字段与四项指标口径本身不变。
- 两种调度算法均为确定性实现，当前不使用随机源；`seed` 仅为接口预留，不影响结果，也不影响日志。
